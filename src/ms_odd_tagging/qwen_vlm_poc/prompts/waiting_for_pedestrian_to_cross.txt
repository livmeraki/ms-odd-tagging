Scenario: waiting_for_pedestrian_to_cross
Definition: Ego is stopped, stopping, or clearly slowing because a pedestrian is crossing, entering, or clearly intending to enter ego's expected path.

Use only these neutral inputs:
1. ordered BEV images;
2. ego_speed_series, a compact speed curve across the scene;
3. pedestrian_tracks_reference, compact observed tracks for candidate pedestrians in one fixed reference frame.

If Model input JSON has focused_evaluation=true, evaluate ONLY primary_pedestrian_id.
Other orange pedestrians are context only. Do not require resolving every visible pedestrian.

HOW TO READ EACH BEV:
- Green vehicle = ego. Ego is re-centered in every BEV, so do not infer speed from ego-icon displacement.
- Orange = pedestrian class.
- Yellow outline + numeric label = candidate pedestrian ID.
- Yellow-brown dotted trail = observed motion of that candidate pedestrian across the scene.
- Cyan line = ego's actual future trajectory from canonical ego poses.
- Translucent light-cyan band = ego future path corridor.
- The trail and corridor are neutral geometry, not precomputed crossing/conflict labels.
- In focused_evaluation=true requests, yellow outline + printed ID marks ONLY the primary pedestrian being evaluated, and the yellow-brown trail belongs to that same primary pedestrian.

The model input intentionally excludes heuristic truth labels such as conflict, crossing, moving_toward_corridor, yielding, ego_response, or temporally_linked. Candidate existence alone does not imply a positive scene.

Require BOTH:
1. Pedestrian/path relation: the primary/candidate pedestrian's observed trail crosses, enters, or clearly moves into/through the light-cyan future ego corridor.
2. Ego response: ego_speed_series shows ego stopped, nearly stopped, stopping, or clearly slowing during that same primary-pedestrian interaction.

Pedestrian/path rules:
- Match the printed numeric pedestrian ID to pedestrian_tracks_reference.
- Use the full yellow-brown observed trail, not one instantaneous pedestrian position.
- A crossing may occur between the displayed BEV snapshots; if the continuous observed trail enters/crosses the light-cyan corridor, do not reject only because one snapshot is outside it.
- Judge crossing against the cyan/light-cyan future path, not lateral_m=0. On a curved road the true future path can be several meters left/right of the instantaneous ego heading centerline.
- pedestrian_tracks_reference is expressed in one fixed reference frame and is provided to make temporal pedestrian motion easy to follow.

Ego-response rules:
- Use ego_speed_series for the scene's speed trend.
- "stationary" MUST be interpreted as "stopped".
- "stationary" alone is NOT sufficient for a positive decision.
- A supported positive reason may state: Ego is stationary, which satisfies the stopped condition.
- Ego does not need to visibly decelerate in a displayed BEV if it is already stopped or nearly stopped while the pedestrian crosses.
- Sustained very-low speed during the crossing satisfies the waiting condition.
- A clear speed decrease leading into the interaction also supports the scenario.

Important negatives:
- A pedestrian whose observed track is parallel to or remains outside the future ego corridor is false.
- Pedestrian proximity alone is false.
- Ego slowing/stopping alone is false.
- Do not invent causal linkage from candidate existence.
- If the observed trail/track does not enter or cross the future ego corridor, prefer false or insufficient_evidence.
- If ego is neither very slow/stopped nor slowing during the interaction, prefer false or insufficient_evidence.

Return JSON with exactly:
recording_id, window_start_frame, window_end_frame, scenario, decision, confidence,
event_start_frame, event_end_frame, primary_object_ids, evidence_ids, reason,
ambiguities, insufficient_evidence, review_required.

Output rules:
- If decision=true, evidence_ids must contain exactly the supplied visual_evidence_id.
- If decision=true, primary_object_ids should contain only the candidate pedestrian ID(s) participating in the interaction.
- If decision=false, primary_object_ids may be [].
- If decision=false, event_start_frame and event_end_frame must be null.
- Keep reason to one short sentence.
